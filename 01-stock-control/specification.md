# Постановка на доработку

## Контекст

Проектная конфигурация — 1С:Управление торговлей. До оценки нужно проверить версию, текущий порядок резервирования, существующие статусы и возможность решить задачу типовыми настройками. Указанные ниже названия статусов условны.

## Сценарий

**Триггер:** пользователь с правом подтверждения переводит заказ покупателя из черновика в статус «Подтверждён».

**Предусловия:** заказ содержит хотя бы одну товарную строку, выбран склад, количество в строках положительно.

**Правила:**

1. Считать доступное количество по складу на момент подтверждения с учётом действующих резервов.
2. Суммировать потребность по одинаковой номенклатуре и применимым аналитикам учёта (характеристика, серия — если используются).
3. Для каждой группы сравнить потребность с доступным количеством.
4. При наличии дефицита не менять статус. Показать список проблемных строк с колонками «Товар», «Требуется», «Доступно», «Не хватает».
5. Если дефицита нет, завершить подтверждение и сохранить дату, время и пользователя.
6. Повторная попытка запускает расчёт заново, без использования прошлого результата.

**Пример сообщения:** «Заказ не подтверждён. Товар А: требуется 12 шт., доступно 8 шт., не хватает 4 шт. Измените количество или согласуйте другой способ исполнения».

## Нефункциональные условия

- Операция не должна оставлять заказ частично подтверждённым при ошибке.
- Проверку одновременных заказов выполнить с учётом фактического механизма резервирования в конфигурации.
- Не менять типовые объекты без отдельного согласования; предпочесть поддерживаемый механизм расширения, если требуется разработка.

## Критерии готовности

Реализованы R-01–R-09, успешно выполнены тесты T-01–T-10, подтверждён способ работы с конкурирующими заказами, подготовлена инструкция пользователя.
