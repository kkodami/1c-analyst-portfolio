# Обследование и требования

## Вопросы для интервью

| Кому | Вопрос | Зачем |
| --- | --- | --- |
| Менеджеру | В какой момент заказ считается обещанным клиенту? | Определить событие проверки |
| Менеджеру | Можно ли подтвердить часть заказа? | Определить действие при дефиците |
| Кладовщику | Как фиксируются резервы и отбор со склада? | Уточнить формулу доступности |
| Кладовщику | Бывают ли несвоевременно отражённые поступления? | Выявить риск неверных остатков |
| Руководителю продаж | Кто вправе обходить запрет? | Определить исключения и права |
| Руководителю продаж | Нужна ли проверка по нескольким складам? | Определить границы решения |
| Администратору 1С | Есть ли типовой контроль и какие доработки уже действуют? | Избежать дублирования |

Ответы в учебном кейсе не получены. Ниже — проектные допущения для демонстрации решения.

## Требования

| ID | Требование | Приоритет | Проверка |
| --- | --- | --- | --- |
| R-01 | Проверять доступное количество при попытке подтвердить заказ | Must | T-01, T-02 |
| R-02 | Считать доступное количество по выбранному складу как остаток минус действующий резерв | Must | T-03, T-04 |
| R-03 | При дефиците показать номенклатуру, требуемое, доступное и недостающее количество | Must | T-02 |
| R-04 | При дефиците оставить заказ неподтверждённым, сохранив введённые данные | Must | T-02 |
| R-05 | После исправления заказа разрешить повторную проверку | Must | T-05 |
| R-06 | Проверять все строки, включая повторяющуюся номенклатуру | Must | T-06 |
| R-07 | Не учитывать отменённые резервы | Must | T-07 |
| R-08 | Фиксировать результат проверки и время подтверждения для разбора спорных случаев | Should | T-08 |
| R-09 | Не допускать подтверждения без выбранного склада | Must | T-09 |

## Открытые решения

- Допустимо ли частичное подтверждение заказа?
- Можно ли подобрать другой склад без изменения заказа?
- Нужен ли руководителю доступ к исключению из запрета?
- Как обрабатываются наборы, характеристики и серии номенклатуры?
- Как избежать одновременного подтверждения двух заказов на один остаток? Нужна проверка механизма резервирования и транзакционности на тестовой базе.

Без ответов на эти вопросы решение нельзя передавать в промышленную разработку как окончательное.
