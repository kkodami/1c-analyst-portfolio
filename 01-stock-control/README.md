# Кейс 1. Контроль остатков при подтверждении заказа

**Учебный заказчик:** ООО «Северная полка», оптовая торговля, два склада, 8 менеджеров. **Ориентир:** 1С:Управление торговлей. Все исходные данные вымышлены.

## Проблема и цель

Менеджер сообщает клиенту, что заказ принят, до проверки доступного остатка. При сборке выясняется, что товара не хватает. Цель — исключить подтверждение недоступного количества и дать менеджеру понятный следующий шаг.

**Границы:** создание и подтверждение заказа покупателя, проверка по выбранному складу, сообщения пользователю. Закупка недостающего товара, доставка и ценообразование вне кейса.

## Как есть

1. Менеджер получает заявку клиента и вводит заказ.
2. Устно или по почте подтверждает его.
3. Кладовщик начинает сборку и сообщает о дефиците.
4. Менеджер меняет заказ и снова согласует его с клиентом.

## Как будет

1. Менеджер вводит заказ и выбирает склад.
2. Перед переводом в статус «Подтверждён» система рассчитывает доступное количество по каждой строке.
3. Если товара хватает, подтверждение проходит. Если нет — система показывает дефицит по строкам и блокирует подтверждение до исправления.
4. После исправления менеджер повторяет проверку и только затем отвечает клиенту.

**Учебные допущения:** проверка проводится по одному складу; доступное количество = остаток минус действующие резервы; отрицательные остатки при подтверждении запрещены. Эти правила нужно согласовать с владельцем процесса.
